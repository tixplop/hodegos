Hodegos 0.2.0 : l'IDE se suffit à lui-même (phase 8). Terminal confiné, réglages des modèles et des mentors, Markdown rendu, création et suppression de fichiers depuis l'arbre. Les mentors guident toujours sans écrire à votre place : la garde « pas de solution » et le cadre commun des prompts sont inchangés.

**Plateforme : Linux x86_64 sous WSL2 uniquement.** Le binaire exige glibc 2.39 ou plus récent (Ubuntu 24.04 ou plus récent). Le terminal intégré demande `bubblewrap` : `sudo apt install bubblewrap`.

## Nouveautés

- **Arbre** : créer un fichier ou un dossier, supprimer (la confirmation dit ce que git peut restaurer), statut git par fichier et branche dans la barre d'état. L'arbre suit les fichiers créés ou supprimés hors de Hodegos.
- **Mentors à la demande** : « Activer X » rend le mentor titulaire et lui demande aussitôt une relecture de la section du curseur. Sélection lisible sur la ligne active.
- **Markdown** : source, aperçu en direct (syntaxe brute seulement sur la ligne du curseur, cases à cocher) et lecture ; Ctrl+E bascule entre édition et lecture.
- **Réglages** :
  - modèle et effort de raisonnement par niveau ; un modèle sans sorties structurées est refusé ;
  - tout changement de niveau est réévalué sur les cas intégrés, après annonce du coût et de la durée estimés (ADR 0007) ; un résultat sous le seuil est signalé, avec retour à l'ancien réglage ;
  - clé d'API (jamais renvoyée au navigateur, `OPENROUTER_API_KEY` prime) et budget mensuel ;
  - `config.toml` garde ses commentaires.
- **Éditeur de mentors** : personnaliser un mentor livré, éditer en formulaire ou en fichier brut, créer, dupliquer, désactiver, revenir au livré ; mêmes règles de validation que le chargeur, erreurs champ par champ ; prompt assemblé visible.
- **Terminal intégré** (bouton « Terminal » ou Ctrl+`) : votre shell dans la racine du projet, confiné par bubblewrap (ADR 0005) : seuls le système en lecture seule, le projet et quelques dossiers de `$HOME` sont visibles ; montages réglables par `[terminal] binds`. Rien de ce qui y passe n'est envoyé aux mentors ; il s'arrête avec l'onglet, la fenêtre ou Hodegos.
- **`hodegos eval`** sans argument joue les cas intégrés au binaire ; les rapports notent les jetons.

## Changements à connaître

- `config.toml` accepte `fast_effort` et `strong_effort` (`default`, `low`, `medium`, `high`) et une section `[terminal]`.
- Un mentor dont le `mode`, le `model` ou l'`entry_level` est inconnu est signalé sur ce champ (avant : « YAML invalide »).
- Seule écriture de Hodegos dans un projet hors de vos fichiers : `.hodegos/mentors/`, à l'enregistrement d'un mentor de projet.

## Installer

```sh
sha256sum -c hodegos-v0.2.0-x86_64-unknown-linux-gnu.tar.gz.sha256
tar -xzf hodegos-v0.2.0-x86_64-unknown-linux-gnu.tar.gz
install -m 755 hodegos-v0.2.0-x86_64-unknown-linux-gnu/hodegos ~/.local/bin/
hodegos --version
```

Configuration et données de la 0.1.0 reprises telles quelles. Le projet doit être dans le système de fichiers Linux (`~/…`), pas sous `/mnt/`.
